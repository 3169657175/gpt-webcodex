# 网页 MCP 助手 0.7.2 发布说明

0.7.2 是一次管理中心 UI 与状态语义修正版，重点解决“服务实际已经可用，但界面仍显示黄色等待或灰色未启动”的误导，以及设置页和侧栏视觉层级混乱的问题。

## 状态语义

- ChatGPT 页面刚打开、尚未观察到第一条消息的 MCP 挂载时，不再把 `waiting-first-attachment` 视为故障或未就绪。
- Runtime、Tunnel 和 OpenAI 上游已经正常时，ChatGPT MCP 显示“就绪”；首次实际调用后再更新为已挂载状态。
- Doctor/诊断页把 `available` 视为正常可用，不再显示黄色警告。
- 仍保留真正的 `unavailable` 状态，避免用绿色掩盖真实挂载失败。

## 首页与启动链路

- 启动链路会根据实时快照回填配置、环境、Runtime、本地 MCP、Tunnel、OpenAI 通道和 ChatGPT MCP 状态。
- 服务整体已就绪时，遗漏的历史 progress 事件不会再让中间方块长期保持灰色。
- “等待”改为明确的“待执行”空心状态；已完成、当前执行和失败分别使用清晰但克制的视觉反馈。
- 已经完成的链路会显示“全部就绪”，而不是继续停留在“进行中”。

## 管理中心 UI

- “配置教程”改成与首页、工作区、本地记忆、设置与诊断一致的标准导航项。
- 左侧“服务运行中”大卡片改为紧凑健康摘要：服务状态、当前工作区、本地工具、连接通道四类信息分层显示。
- 移除过重渐变、阴影和大圆角，收紧侧栏、顶部栏、卡片、按钮与正文间距。
- 设置页重新分为“常用设置”“外观与行为”“连接与运行”“诊断与维护”，常用项优先，高级项按需展开。
- 宽屏下常用设置与外观行为并排展示，小窗口自动切回单列。

## 验证

- 增加 0.7.2 管理中心专项回归测试。
- 覆盖统一导航、紧凑侧栏、设置分组、首次 Attachment 语义、启动链路实时收口、Desktop/Runtime 版本一致性。
- 发布构建继续执行完整 Node/Python 测试、Schema 契约检查与 Windows NSIS 打包。
